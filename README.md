# Tech Blogs

A public, read-only website that aggregates engineering blog posts from ~40 hand-curated top tech companies, categorizes them with a fixed taxonomy, and shows an LLM-written summary for each post with a link to the original. See `CONTEXT.md` for the domain vocabulary and `docs/adr/` for key decisions.

**Architecture:** fully static, $0/month hosting.

```
GitHub Actions (cron, every 6h)
  ├─ ingest   → parse 39 RSS/Atom feeds → new rows in data/posts.db (metadata only)
  ├─ enrich   → fetch article text transiently → Gemini: 1-3 categories + summary
  ├─ commit   → data/posts.db pushed back to the repo (feeds forget old items; the DB is the archive)
  ├─ build    → Astro renders firehose + category pages + source pages
  └─ deploy   → GitHub Pages
```

## Local usage

```sh
npm install
npm run ingest                         # pull feeds into data/posts.db
ANTHROPIC_API_KEY=... npm run enrich   # classify + summarize pending posts
npm run dev                            # local site at localhost:4321
npm run build                          # static site in dist/
```

**LLM provider:** the enrich step uses Claude when `ANTHROPIC_API_KEY` is set, Gemini when `GEMINI_API_KEY` is set (set `LLM_PROVIDER=anthropic|gemini` to force one when both exist). Models via `ANTHROPIC_MODEL` (default `claude-opus-4-8`) / `GEMINI_MODEL` (default `gemini-2.5-flash`). Other knobs: `ENRICH_LIMIT` (posts per enrich run, default 60).

Re-run classification after changing `taxonomy.json` or the prompt:

```sh
node scripts/reclassify.mjs --all        # or --source <slug> / --category <slug>
GEMINI_API_KEY=... npm run enrich
```

## One-time setup

1. **LLM key**: an Anthropic API key (https://platform.claude.com) to run on Claude, or a free-tier Gemini key (https://aistudio.google.com/apikey).
2. **GitHub**: push this repo, then add the key as a repository secret (Settings → Secrets and variables → Actions): `ANTHROPIC_API_KEY` **or** `GEMINI_API_KEY`. Switching providers later = delete one secret, add the other; optionally run `node scripts/reclassify.mjs --all` first if you want existing summaries regenerated by the new model.
3. **GitHub Pages**: Settings → Pages → Build and deployment → Source: **GitHub Actions**
4. Run the workflow manually once (Actions → "Ingest, enrich & deploy" → Run workflow).

**Cost control:** the seed backlog is parked — only the 20 newest posts are queued for enrichment at first (plus whatever gets published going forward). To enrich the full ~600-post backlog later, run `node scripts/skip-backlog.mjs --restore` and commit `data/posts.db`; runs then work through it gradually (`ENRICH_LIMIT` per run). `scripts/skip-backlog.mjs --keep N` re-parks all but the newest N.

The site lands at `https://<owner>.github.io/<repo>/` — the workflow computes the base path from the repo name automatically, so any repo name works.

## Editing the source list

`sources.json` — one entry per Source (`slug`, `name`, `feed_url`). A blog without a working feed cannot be a Source. After adding one, the next pipeline run picks it up.

## Notes

- Only posts that have a summary are shown on the site; publisher text is never displayed and article text is never persisted (see `docs/adr/0001-summaries-not-republication.md`).
- Feeds only expose recent items, which is why `data/posts.db` is committed: it is the site's memory.
- Some feeds (Uber, Spotify, Shopify, DoorDash) aggressively block non-browser clients and are excluded; revisit if they loosen up.
