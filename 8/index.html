Partition Finalization in Pinterest’s Next-Generation DB Ingestion Framework ↗

In streaming database ingestion frameworks, continuous commits make it difficult for downstream batch jobs to know when a time partition contains complete data and is safe to process. Pinterest solved this by building an event-time partition finalization mechanism directly into their Flink-to-Iceberg sink using extensible accumulators and commit processors. During Flink checkpointing, per-subtask event-time statistics are summarized using compact t-digest sketches and written into Iceberg snapshot summaries. A commit processor then evaluates these statistics across recent commits to generate a non-regressing watermark published as an Iceberg table property, which downstream jobs query via sensors to gate execution. This architecture eliminates external coordination services and provides configurable policies to trade off data completeness against freshness.

How Cloudflare addressed a cross-tenant data exposure vulnerability in Containers ↗

A cross-tenant data exposure vulnerability in Cloudflare Containers allowed workloads on multi-tenant hosts to read residual data from storage blocks previously used by other customers. The issue stemmed from Linux device mapper thin provisioning (dm-thin) configured with skip_block_zeroing, which allocated physical 64 KiB blocks upon small writes without zeroing out the remaining unwritten space. Cloudflare mitigated the vulnerability by disabling skip_block_zeroing across its fleet, retiring active container disks, and clearing pre-mitigation cached image layer snapshots. Analysis of historical disk-I/O telemetry confirmed no evidence of unauthorized exploitation prior to remediation.
