Unraveling a Postgres segfault that uncovered an Arm64 JIT compiler bug ↗

Datadog investigated a series of segmentation faults occurring in Postgres clusters running on Arm64 Kubernetes nodes, tracing the root cause to LLVM JIT compilation bugs. By debugging down to the assembly level, they discovered that position-independent code generated for switch statements was failing relocation checks because the distance between the .text and .rodata memory sections exceeded the 2 GiB limit imposed by the AArch64 ABI. This mismatch between Linux's memory allocation hints and Arm64 architectural constraints caused pointers to resolve incorrectly, leading to infinite loops or crashes.

Mitigation required temporarily blocking traffic at the CDN level, increasing baseline task resources, and incrementally restoring traffic alongside fixing the telemetry bug.

The big ideas behind retrieval augmented generation ↗

Large language models often struggle with hallucinations and lack access to proprietary or real-time data. Retrieval augmented generation (RAG) addresses this by using semantic search to retrieve relevant private data chunks and injecting them directly into the LLM's prompt context. To implement this efficiently, developers must balance chunking strategies—such as token-based chunking, token overlap, and surrounding chunk retrieval—to maintain semantic precision without exceeding token limits or driving up API costs. Elasticsearch simplifies this architecture by automating text chunking, generating vector embeddings, and providing an interactive playground to test and export RAG application code.
