Cross-request KV cache exposure in the GLM-5.3 Workers AI model, and our remediation with SGLang ↗

Cloudflare published a postmortem detailing a tenant isolation vulnerability in their Workers AI platform where requests to the GLM-5.3 model exceeding 681,280 tokens returned stale KV cache data from prior users' sessions. The leak was caused by a configuration mismatch between the engine's KV cache pool size and the model's context length, combined with an SGLang bug in disaggregated prefill/decode mode that generated decode responses over uninitialized cache pages after prefill rejections. Cloudflare resolved the issue by expanding prefill cache allocations, patching SGLang to drop rejected requests at admission before remote memory transfers occur, and updating upstream dependencies. To mitigate similar memory-safety risks, Cloudflare is working with SGLang maintainers to implement deferred page releases, KV transfer checksums, and formal verification of RDMA-based transfer protocols.
