How v0 authenticates to Snowflake without exposing the user's OAuth token ↗

To prevent AI-generated applications running in sandboxes from exfiltrating sensitive credentials via prompt injection, Vercel developed a server-side Snowflake request proxy for v0. The proxy intercepts sandbox network traffic using custom firewall TLS termination, resolves the user's OAuth token out-of-band via OIDC sandbox bindings, and injects credentials strictly into protocol-defined authentication fields. Instead of raw tokens, sandboxes receive public placeholder strings, and any request where a placeholder appears in caller-controlled payloads like SQL text fails closed. In its first 15 days in production, the proxy attached credentials across roughly 13,000 requests without exposing long-lived OAuth tokens to untrusted generated code.
