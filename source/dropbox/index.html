Improving infrastructure efficiency for growing demand in the age of AI ↗

To meet rising compute and storage demands from AI features within physical power and cooling constraints, Dropbox optimizes its hybrid datacenter infrastructure as a unified system. The company uses automated algorithms to put idle hardware into a low-power Deep Sleep mode, dynamically rebalances workloads across the active fleet, and adopts high-density Shingled Magnetic Recording (SMR) drives. To support power-dense seventh-generation servers without rebuilding facilities, engineers doubled the power distribution units per rack using existing busways. Through these combined fleet and physical optimizations, Dropbox reduced its storage power consumption per unit of data (watts per petabyte) by more than 50% since 2020.

How our universal content processing platform Riviera evolved for AI and beyond ↗

Dropbox's universal content processing platform, Riviera, evolved from a simple file preview generator into a highly scalable, shared service that powers search indexing, video transcoding, and AI data ingestion. To handle over 300 file formats, Riviera uses a plugin-based architecture that decomposes complex workflows into reusable, atomic transformations managed by dedicated backend workers. This separation of coordination and execution allows product teams to easily add support for new file types without modifying the core system. By caching responses and validating requests centrally, the platform reliably processes hundreds of thousands of transformations per second, and Dropbox is now exposing these capabilities to external developers via public APIs.

How we used DSPy to turn AI evaluations into better responses in Dash chat ↗

Dropbox developed an automated evaluation and optimization pipeline for its Dash chat agent using the DSPy framework. The system first calibrates LLM-as-judge evaluations against human-labeled trajectory data to ensure scoring reliability across multi-step agent interactions. These calibrated judges then provide structured feedback signals to automatically optimize the agent's system prompts using algorithms like GEPA and MIPROv2. This feedback loop nearly doubled prompt iteration velocity, reducing incomplete answers by 26 percent and token usage by 5.4 percent without degrading quality.

Improving storage efficiency in Magic Pocket, our immutable blob store ↗

Dropbox's core exabyte-scale blob storage system, Magic Pocket, suffered from severe storage fragmentation and high overhead due to an incident that generated a large tail of under-filled volumes. To address the limitations of its steady-state compaction strategy, the team introduced a multi-layered compaction architecture featuring dynamic programming-based volume grouping (L2) and a streaming re-encoding pipeline (L3) to complement existing steady-state consolidation (L1). By combining these strategies with automated eligibility thresholds and strict resource safeguards, Dropbox successfully drove storage overhead down below previous baselines and improved overall fleet efficiency.

Reducing our monorepo size to improve developer velocity ↗

Dropbox tackled severe developer velocity bottlenecks caused by its server monorepo swelling to 87GB, which pushed clone times past an hour and threatened GitHub's size limits. Investigation revealed that Git's default 16-character path heuristic for delta compression paired internationalization files across different languages rather than within the same language, bloating pack files. Working with GitHub, the team executed an aggressive server-side repack using tuned window and depth parameters. This reduced the repository size by 77% to 20GB, cut initial clone times to under 15 minutes, and improved CI pipeline reliability without disrupting production workflows.

How we optimized Dash's relevance judge with DSPy ↗

Dropbox needed to scale its Dash relevance-judging pipelines while reducing costs by migrating from expensive large language models to smaller open-weight alternatives. To solve the problem of prompt brittleness across model swaps, the team implemented DSPy to systematically optimize prompts against a measurable objective based on human-alignment metrics and structural reliability. The approach reduced normalized mean squared error by 45 percent when adapting to new models and cut malformed JSON outputs by over 97 percent on smaller, more brittle models. Additionally, they introduced a constrained instruction-library layer for production models to enable safe, incremental prompt improvements without destabilizing existing behaviors.

Using LLMs to amplify human labeling and improve Dash search relevance ↗

Dropbox improves the search relevance models for its Dash enterprise search engine by using a hybrid labeling approach that combines human judgment with LLM-assisted evaluation. Because training high-performance ranking models requires massive amounts of graded relevance data that is expensive and difficult to gather purely through manual annotation, the system uses a small, high-quality set of human-labeled internal data to calibrate and prompt-tune an LLM. This LLM then acts as a force multiplier, generating hundreds of thousands of scaled relevance labels used offline to train production ranking models like XGBoost. By incorporating contextual research tools, error-driven document sampling, and prompt optimization frameworks like DSPy, Dropbox successfully scales its training data pipeline while maintaining compliance and accuracy.

How low-bit inference enables efficient AI ↗

Dropbox examines the implementation of low-bit inference techniques like quantization to maintain performance and reduce the resource footprint of large attention-based models in production. The post details the mechanics of pre-MXFP approaches—such as A8W8 and A16W4 using AWQ and HQQ—alongside newer hardware-accelerated MXFP and NVFP formats that leverage GPU Tensor Cores. It outlines the trade-offs between memory bandwidth savings and compute overhead, highlighting how fine-grained block-scaling and proper choice of quantization format mitigate accuracy loss. Ultimately, these optimizations allow products like Dropbox Dash to deliver fast, cost-effective AI capabilities while respecting strict hardware and latency constraints.
