Session revocations at scale ↗

Canva addressed a critical performance bottleneck during deployments where hundreds of thousands of gateway instances simultaneously overloaded their MySQL database by loading large in-memory session revocation caches. They engineered a new system that leverages S3 as an intermediary cache. Asynchronous worker processes continuously partition revocation records into compact, sorted 30-minute binary chunks and upload them to S3 using optimistic concurrency control. Gateway pods now efficiently download these chunks directly from S3 on startup and for continuous updates, eliminating the database stampede. This solution dramatically improved deployment speeds, reduced MySQL read replicas, and decreased the in-memory cache footprint by 87.5%.

The foundations of Canva’s continuous data platform with Snowpipe Streaming ↗

Canva needed to scale its product analytics platform while reducing high cloud costs driven primarily by the 5 KB minimum billing record size of AWS Data Firehose when pushing data to Amazon S3. To solve this, the engineering team replaced Firehose with Snowflake's Snowpipe Streaming API, integrating it directly with Kinesis Data Streams using the Kinesis Client Library. By mapping Kinesis shards to Snowpipe Streaming channels and instantiating one client per shard to handle work-stealing invalidations, Canva successfully processed over 20 PiB of data. This architectural shift lowered time-to-query latency to ten minutes and reduced overall platform cloud spend by 45%.

Canva incident report: API Gateway outage ↗

Canva details a critical outage of canva.com caused by a combination of CDN network routing issues, a delayed frontend asset load, and a thundering herd problem that overwhelmed their API Gateway. Slow asset fetching through Cloudflare due to a stale traffic management rule caused hundreds of thousands of client requests to queue up via cache streaming. When the asset finally loaded, it triggered a massive traffic spike that collided with a pre-existing performance regression in a telemetry library, causing severe lock contention on event loop threads. This memory pressure and CPU starvation triggered cascading Linux OOM kills across all API Gateway tasks. Mitigation required temporarily blocking traffic at the CDN level, increasing baseline task resources, and incrementally restoring traffic alongside fixing the telemetry bug.

The science of routing print orders ↗

Canva needed to optimize the global routing of print orders across multiple disparate suppliers to minimize delivery times and carbon emissions. They built a decoupled routing engine using a plug-and-play architecture that separates graph traversal from the decision-making logic. By asynchronously synchronizing relational data into regional Redis cache graph shards, the system achieves sub-20-millisecond query latencies. The traversal engine utilizes a modified min-cost-flow algorithm equipped with a regret mechanism to handle constraints and ensure deterministic, explainable path selection.
