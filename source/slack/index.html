Shipyard: How We Built Slack’s Next-Generation EC2 Platform ↗

Slack developed Shipyard, a next-generation EC2 platform designed to replace long-lived mutable instances with immutable, layered machine images and automated lifecycle management. The system separates preparation into bake and provision phases to achieve fast boot times, integrates with a global deployment orchestrator for progressive rollouts, and utilizes an automated service called the Reaper to continuously cycle and refresh instances. This architecture eliminates configuration drift, enhances security compliance, and gives engineering teams predictable deployment primitives for workloads that cannot easily be containerized.

Agentic Testing: Where Agents Fit in the E2E Testing Stack ↗

Slack evaluated the viability of using LLM-driven autonomous agents for end-to-end user interface testing by running over 200 automated workflows across different execution models, including the Playwright Model Context Protocol (MCP), Playwright CLI, and agent-generated test scripts. The experiments measured reliability, execution speed, and token-based costs on workflows of varying complexity. The results demonstrated that while agentic testing offers high adaptability by validating high-level goals rather than rigid click paths, it currently suffers from high computational costs, longer execution times, and context growth issues that make it impractical for frequent CI pipelines. Consequently, the team positions agentic testing not as a replacement for deterministic tests, but as a complementary exploratory layer at the top of the testing pyramid suited for tasks like debugging and reproducing complex behaviors.

From SSH to REST: A Security-Driven Modernization of Slack’s EMR Data Pipelines ↗

Slack modernized its data infrastructure by eliminating over 700 production SSH-based operators that executed critical data pipelines on AWS EMR clusters. The organization migrated these workloads to a REST-based architecture using a centralized gateway called Quarry alongside Apache YARN Distributed Shell for running arbitrary shell commands. This transition successfully reduced the security attack surface, eliminated master node resource contention, and provided robust server-side job tracking and observability. The zero-downtime migration spanned eight independent data regions and unblocked broader cloud-native initiatives such as migrating to child accounts and Spark on Kubernetes.

Managing context in long-run agentic applications ↗

Building long-running, multi-agent AI systems requires solving the problem of context window saturation and reasoning drift caused by accumulating stateless API message histories. Slack's engineering team designed a context management architecture using three specialized channels: a Director's Journal for structured working memory, a Critic's Review for credibility-scored finding validation, and a Critic's Timeline for verified chronological event reconstruction. By replacing raw message history accumulation with these targeted context resources, the system prevents token degradation and hallucination propagation across multi-round investigations. This approach successfully maintains agent alignment and long-run coherence without hitting API context limits during complex security alert analyses.

From Custom to Open: Scalable Network Probing and HTTP/3 Readiness with Prometheus ↗

When Slack rolled out HTTP/3 support on their edge infrastructure, they discovered a critical lack of client-side observability because existing commercial SaaS tools and the Prometheus Blackbox Exporter lacked native support for the underlying QUIC transport protocol. To overcome this gap, an intern integrated the quic-go client into the Prometheus Blackbox Exporter and open-sourced the contribution for the wider community. Slack then deployed this custom-built in-house system to probe hundreds of thousands of HTTP/3 endpoints, achieving a unified Grafana dashboard for HTTP/1.1, HTTP/2, and HTTP/3 metrics. This setup enabled reliable alerting and faster debugging, proving that establishing robust monitoring is a vital precursor to major protocol migrations.

How Slack Rebuilt Notifications 📣 ↗

Slack overhauled its legacy notification system to eliminate user overwhelm caused by conflicting preference models, hidden coupling between in-app awareness and push alerts, and inconsistent multi-client states. The engineering team migrated millions of users from four separate paradigms into a single unified preference model by decoupling message activity from push notifications and introducing a read-time migration strategy. To achieve seamless cross-platform parity, they rewrote foundational mobile UI code and updated backend database schemas with robust fallbacks for safe rollbacks. This architectural simplification resulted in a fivefold increase in settings engagement, a significant drop in customer support tickets, and predictable notification behavior across desktop and mobile clients.

Streamlining Security Investigations with Agents ↗

Slack's security team transitioned from a rudimentary single-prompt prototype to a multi-agent orchestrated architecture to automate security alert investigations. The system relies on distinct agent personas including a Director, domain Experts, and a Critic that use structured outputs and a weakly adversarial loop to verify evidence and minimize hallucinations. This decoupled design allows the service to strategically allocate model costs using a knowledge pyramid while seamlessly integrating with existing detection pipelines via a dedicated hub and worker architecture. As a result, the automated workflow successfully surfaces nuanced security risks and unprompted secondary vulnerabilities that traditional static rules often miss.
