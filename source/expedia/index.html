Focus on the Feature, Not the Fixture: GenAI powered GraphQL mocks ↗

Manual GraphQL mock generation is time-consuming and fragile because schema updates frequently break handwritten fixtures. To address this, Expedia built mockql-rs, a Rust CLI tool that leverages LLMs to generate contextual, schema-valid mock responses directly from GraphQL operations annotated with a @mock directive. The tool splits queries into real and mocked fields, fetches real data from the upstream server, and prompts an LLM to populate the remaining fields using the schema and upstream context. This approach enables frontend developers to prototype against incomplete APIs without creating brittle JSON fixtures or waiting for backend resolver implementations.

Using LLMs to Analyze Spark SQL Plans: A Practical Approach to Debugging Long-Running Jobs ↗

Debugging complex Spark SQL execution plans at scale often requires wading through massive physical graphs and fragmented metrics to find hidden performance bottlenecks like data skew, missing filters, and suboptimal join strategies. Expedia built an automated, LLM-powered workflow that ingests structured Spark history server metadata and uses pattern-guided prompting to detect specific anti-patterns with strict evidentiary traceability. By mapping findings back to exact stage, node, and task IDs rather than relying on free-form chat, the system delivers actionable, structured JSON remediations. Applying these insights to real workloads reduced query runtimes by 40% to 95% and cut compute costs significantly without requiring manual deep dives into Spark internals.

The Most Expensive Milliseconds Are Unmeasured ↗

Expedia tackled the problem of silent mobile performance degradation during user login flows, where traditional metrics like crashes, ANRs, or backend latency failed to capture actual screen readiness. To bridge this observability gap, the engineering team introduced Native Time to Interactive (NTTI), a custom metric measuring the time from screen start to the final key component rendering on both iOS and Android. Implementing NTTI exposed hidden platform-specific performance deltas, validated technology stack migrations, and prevented regressions before wider production rollouts. Ultimately, this screen-level metric shifted ownership, turning performance monitoring into a core engineering discipline shared by product, design, and engineering teams.

Operating Trino at Scale With Trino Gateway ↗

Scaling analytics platforms with large distributed SQL query engines often leads to bottlenecks caused by high concurrency and mixed workloads sharing the same underlying infrastructure. To solve this, Expedia implemented Trino Gateway to act as an intelligent proxy and load balancer, routing queries to specialized clusters based on workload types such as adhoc analysis, heavy ETL processing, and high-concurrency BI dashboards. They further contributed UI improvements, enhanced cluster health monitoring, and flexible routing rule management directly to the open-source project. These enhancements eliminated manual configuration files and enabled seamless query isolation, resulting in improved cluster responsiveness and easier operational management.

Interleaving for Accelerated Testing ↗

Expedia Group addresses the slow sample size requirements and long durations of traditional A/B tests for low-conversion lodging recommendations by implementing interleaving testing. By blending results from competing ranking variants into a single list presented to users simultaneously, the system evaluates relative user preferences with a 10x to 100x increase in sensitivity. The platform uses event attribution for clicks and bookings, paired with fast t-tests on winning indicators, to quickly prune ineffective ranking models before running final, lower-risk A/B tests.
