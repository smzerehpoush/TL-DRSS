How we built the Microsoft Learn MCP Server ↗

Microsoft built a remote Model Context Protocol (MCP) server on Azure App Service to give AI agents direct, standardized access to official Learn documentation and code samples. Instead of exposing raw backend APIs, the system uses the C# MCP SDK to provide three agent-optimized tools—search, fetch, and code sample search—backed by the existing Learn content vector store. Operating the remote endpoint required addressing distributed systems challenges such as cross-region deployments, session affinity, and defensive schema evolution for hardcoded clients. This protocol-driven architecture allows any MCP-compatible agent to dynamically discover tools, reduce custom client integrations, and ground responses in up-to-date technical content.

Diagnosing instability in production-scale agent reinforcement learning ↗

Production-scale reinforcement learning for tool-using AI agents often suffers from late-phase instability that remains invisible to standard aggregate metrics like loss, reward, and global KL divergence. This issue stems from variance amplification in tool-conditioned contexts, where exposure to low-support regions of the reference policy causes importance-weighted updates to develop heavy right tails. To address this hidden failure mode, Microsoft developed the Post-Training Toolkit to provide in-stream, slice-aware diagnostics across distributed training ranks. The framework tracks lightweight statistics such as rolling percentiles and effective sample size separately for text-only and post-tool interactions, catching emerging instabilities early enough to apply targeted guardrails.

Common annotated security keys ↗

Microsoft introduces the Common Annotated Security Standard (CASK) to improve the detection and management of security tokens. By incorporating fixed signatures, checksums, and high-entropy alphanumeric strings, the standard enables scanners to identify secrets with near-zero false positives. This approach allows organizations to implement aggressive, automated blocking of leaked keys in source code without disrupting developer workflows. The standard also includes metadata like creation timestamps and dedicated test keys to facilitate better security lifecycle management and rotation policies.

Managed DevOps Pools – The Origin Story ↗

Microsoft faced significant inefficiencies and security risks due to over 5,000 fragmented, self-hosted Azure DevOps pools managed by individual teams. This transition reduced CI/CD infrastructure costs by over 60% and improved developer productivity by eliminating the need for teams to maintain their own build infrastructure. Following this internal success, Microsoft launched Managed DevOps Pools to provide these same capabilities to external customers.
