How v0 authenticates to Snowflake without exposing the user's OAuth token ↗

To prevent AI-generated applications running in sandboxes from exfiltrating sensitive credentials via prompt injection, Vercel developed a server-side Snowflake request proxy for v0. The proxy intercepts sandbox network traffic using custom firewall TLS termination, resolves the user's OAuth token out-of-band via OIDC sandbox bindings, and injects credentials strictly into protocol-defined authentication fields. Instead of raw tokens, sandboxes receive public placeholder strings, and any request where a placeholder appears in caller-controlled payloads like SQL text fails closed. In its first 15 days in production, the proxy attached credentials across roughly 13,000 requests without exposing long-lived OAuth tokens to untrusted generated code.

How we migrated the database behind every Vercel build ↗

Vercel migrated the state behind its build warm pool from Redis to DynamoDB to ensure long-term durability for critical data like billing mappings. The zero-downtime migration relied on feature flags, dual writes, and shadow reads to validate state consistency between both stores. However, DynamoDB's higher read latencies exposed an existing N+1 query issue in the supply loop that had previously been hidden by Redis's sub-millisecond speed. Engineers resolved the resulting stalls by redesigning the database schema around container IDs and refactoring the supply loop to execute checks concurrently.

A sandbox without a network boundary is only half a sandbox ↗

Executing untrusted code or AI-generated programs requires controlling network egress alongside compute isolation to prevent data exfiltration, credential theft, and internal network probing. Vercel Sandbox addresses this by running a host-level firewall outside the microVM that transparently filters outbound TCP and DNS traffic using SNI inspection and CIDR rules. The system safely injects API credentials at the host boundary via ephemeral TLS termination so bearer tokens never enter the microVM. Additionally, developers can dynamically update network policies throughout a workload's lifecycle and route select HTTPS requests through custom proxies for programmable policy enforcement.
