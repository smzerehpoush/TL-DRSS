Instagram Data Saver Mode ↗

Instagram implemented a Data Saver Mode for Android to address high data consumption in markets with limited or expensive cellular connectivity. The engineering team introduced three primary levers: disabling video prefetching, disabling video autoplay, and allowing users to restrict high-resolution media to Wi-Fi only. By testing these configurations globally, the team identified an optimal balance that significantly reduced cellular data usage while maintaining acceptable app performance and engagement. The final feature, which defaults to disabling video prefetching and restricting high-resolution media to Wi-Fi, successfully improved the experience for data-conscious users.

Powered by AI: Instagram’s Explore recommender system ↗

Instagram's Explore recommender system handles billions of content pieces by utilizing a custom domain-specific language called IGQL to streamline candidate generation and experimentation. To manage computational load, the team implemented account-level embeddings using an ig2vec framework and a three-stage ranking funnel that employs model distillation to preselect relevant candidates. This tiered architecture balances ranking quality with latency by progressively applying more complex neural network models to smaller subsets of content. These optimizations allow the system to process 65 billion features and generate 90 million predictions per second.

Python at Scale: Strict Modules ↗

Instagram faced significant challenges scaling its massive Python monolith, including slow server startup times and unpredictable runtime behavior caused by import-time side effects and mutable global state. To address these issues, the team introduced 'strict modules,' a new module type that enforces purity at the top level and restricts modifications to global state. By using custom AST transformations and abstract interpretation, the system ensures that module imports are side-effect-free and classes are immutable, which improves reliability and enables future optimizations like faster, incremental reloads. This approach allows the team to maintain the flexibility of Python while imposing the discipline necessary for a large-scale, high-velocity codebase.

Making instagram.com faster: Part 3 — cache first ↗

To improve page load times, Instagram implemented a cache-first rendering strategy that immediately displays stale feed data stored in IndexedDB while fetching fresh content in the background. To prevent race conditions where user interactions like likes or comments are lost when the server response arrives, the team developed a staging mechanism inspired by Git rebasing. This system captures user actions during the fetch period and replays them onto the updated server state. This approach resulted in significant improvements to display-done times for both the feed and stories tray, aligning web performance more closely with native mobile experiences.

To facilitate testing without requiring iOS 13 beta builds, the team developed a 'fake dark mode' feature that forced the app to render dark styles on older OS versions.
