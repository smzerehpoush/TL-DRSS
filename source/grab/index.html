Building Jarvis Pro: Route first, answer later ↗

To prevent fluent but operationally inaccurate recommendations from an AI assistant built for account managers, Grab designed Jarvis Pro around a "route first, answer later" architecture. Before generating responses, an LLM classification step determines the task category, required context, tool paths, guardrails, and access constraints. The system handles memory scope checking early, consolidates data warehouse queries, and normalizes metric definitions across surfaces to avoid data discrepancies. In offline launch-readiness evaluations, this layered approach achieved 99.4% safe routing accuracy across 351 prompts and increased average answer-quality scores from 78.5 to 91.0 on key portfolio test suites.

Crowdsourced taxonomy verification: A feedback-driven framework for refining knowledge graph relationships via online search interactions ↗

Automated knowledge graph construction using Large Language Models often introduces semantic hallucinations and incorrect taxonomy links that degrade search relevance. Grab developed a closed-loop, feedback-driven verification engine that tests unverified graph edges by injecting them into live search interfaces alongside verified results using an exploration-exploitation strategy. The system tracks fine-grained user micro-interactions—such as clicks, add-to-cart actions, and skips—and converts them into normalized confidence scores. Edges exceeding a verification threshold are permanently promoted to the production graph, while underperforming links are pruned, maintaining high taxonomy quality without manual curation.

Migrating Counter Service storage: Design choices and learnings ↗

Grab migrated its anti-fraud Counter Service handling billions of daily requests from a wide-column store to Aerospike to reduce infrastructure costs and improve latency. The team decoupled the storage layer from business logic using a concrete facade with enum dispatch and redesigned the data model by collapsing multiple time-bucket rows into a single map-based record per counter. This schema redesign reduced disk footprint by two-thirds, cut node costs by half, improved p99 read latency by 50%, and eliminated the previous multi-step read-modify-write pattern on the write path. Safe deployment was achieved through shadow reading and writing with zero downtime.
