Optimizing ML Workload Network Efficiency (Part I): Feature Trimmer ↗

Pinterest addressed a severe network bottleneck in its root-leaf machine learning serving architecture where transmitting unneeded features from root feature-processing nodes to GPU leaf inference nodes restricted performance. The engineering team built Feature Trimmer, a system that extracts required features directly from model signatures and dynamically syncs per-model allowlists with deployment pipelines. This optimization allowed Pinterest to downsize root and leaf clusters, unlocking over $4 million in annual infrastructure savings.

Finding zombies in our systems: A real-world story of CPU bottlenecks ↗

Pinterest engineers investigated mysterious network connectivity failures and driver resets crashing distributed Ray machine learning training jobs on AWS Kubernetes clusters. Through per-core CPU profiling and temporal stack analysis, the team discovered that a default Amazon ECS agent in the base AMI was continuously crash-looping and leaking kernel memory cgroups. This accumulation of nearly 70,000 zombie cgroups caused occasional single-core CPU starvation, which blocked critical AWS ENA network driver threads and triggered device resets. Disabling the unwanted ECS agent service across base images successfully eliminated the cgroup leaks, restored network stability, and brought training job success rates back to expected levels.
