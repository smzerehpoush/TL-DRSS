How the Tinder iOS App reduced the size of our localizations by 95% using Emerge ↗

Tinder faced significant bloat in its iOS app due to shipping thousands of small localization files that incurred a 4KB minimum code-signing size overhead per file. To solve this, the engineering team built custom Bazel rules to transitively collect and merge target-level strings into a single file per language, then integrated Emerge's SmallStrings tool to compress keys and values into LZFSE formats. This automated pipeline successfully reduced the app's download size by 10.7MB and its overall install size by 51.3MB without changing developer workflows.

How Tinder Eased Development Pain With Ignis ↗

Tinder engineers faced a major development bottleneck because testing microservices required pushing code to feature branches and deploying to shared staging environments. To accelerate this feedback loop, they built Ignis, a Go-based CLI tool that lets developers run a single service locally while proxying traffic to and from a shared Kubernetes cluster. Ignis uses a custom Smart Router and an API gateway to dynamically intercept and forward requests based on special headers, enabling multi-tenant local debugging and integration testing. This system eliminated numerous staging environments, cut cloud costs, and significantly improved feature delivery speed.

Identifying vulnerabilities in GitHub Actions & AWS OIDC Configurations ↗

Tinder Security Labs identified widespread vulnerabilities in how organizations configure OpenID Connect (OIDC) between GitHub Actions and AWS. Misconfigured IAM trust policies often fail to restrict the 'sub' (subject) claim, allowing unauthorized external repositories to assume sensitive AWS roles. The team released an open-source black-box assessment tool to help organizations scan their own infrastructure for these risky configurations. Mitigation requires updating trust policies to strictly validate the repository and organization claims within the OIDC token.

How to Categorize and Prevent Risks of Sensitive Links in URLScan ↗

Security researchers at Tinder identified that automated security integrations with URLScan often inadvertently expose sensitive internal links to the public. By querying URLScan's public index, they discovered accessible magic links for file-sharing services, SaaS registration portals, and SSO invitation flows that could allow unauthorized access to corporate systems. The team mitigated these risks by coordinating with URLScan to remove indexed sensitive data and recommends that organizations audit their security vendors' API configurations. Specifically, companies should ensure that automated URL scanning tools are set to private or unlisted visibility to prevent sensitive internal URLs from being indexed.
