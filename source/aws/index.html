Building multi-Region resiliency for AWS CloudFormation custom resource deployment ↗

AWS CloudFormation custom resources lack native multi-Region support, posing challenges for resilient deployments such as duplicate execution, lack of distributed locking, and no automated failover. This article presents an active-active multi-Region architecture to address these issues. The solution leverages cross-Region SNS fan-out to SQS queues in primary and secondary regions, with DynamoDB Global Tables providing distributed locking and idempotency to prevent duplicate processing. Automated failover is managed by Amazon Application Recovery Controller (ARC). This design ensures high availability, correctness, and automation for mission-critical custom resource operations across AWS Regions.

How bitdrift scaled to 121 million concurrent gRPC connections on Amazon CloudFront for live telemetry sporting events ↗

When handling a massive surge of 121 million concurrent gRPC connections during live cricket broadcasts, bitdrift experienced severe origin outages due to a thundering herd problem. The root cause was Amazon Route 53's weighted routing policy, which returned only a single IP address per DNS query to CloudFront edge nodes and caused all persistent connections to pin to a single Network Load Balancer. By switching to Multi-Value Answer routing, which immediately returns up to eight IPs and incorporates integrated health checks, the architecture successfully distributed traffic across multiple origin endpoints. This zero-code DNS configuration change eliminated server-side errors entirely and allowed the system to seamlessly absorb peak traffic exceeding 110,000 requests per second.
