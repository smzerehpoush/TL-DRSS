How to structure a log ↗

Inconsistent and unstructured logs hinder production debugging and make querying or aggregating system events difficult. To solve this, developers should adopt a strict convention of stable, dot-notated event names (like domain.action) and flattened attribute keys instead of nested JSON objects. Restricting log attributes to primitive values or arrays of primitives ensures that logging backends can index and search the data predictably. These patterns can be programmatically enforced across codebases using custom ESLint rules to maintain consistency and prevent sensitive or unqueryable data from leaking into log streams.

No more monkey-patching: Better observability with tracing channels ↗

Traditional application performance monitoring in server-side JavaScript relies heavily on runtime monkey-patching or brittle module customization hooks, approaches that break down as the ecosystem transitions to immutable ES Modules. To eliminate these workarounds, libraries can instead become active participants in their own observability by using Node.js Tracing Channels—a zero-cost, cross-runtime primitive that standardizes event emission and context propagation. This allows library maintainers to expose internal operation lifecycles via decoupled data contracts without coupling to specific APM vendors. Major JavaScript libraries and frameworks like undici, fastify, and ioredis have already begun natively shipping this support.
